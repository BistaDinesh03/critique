# Contributor tracking

Critique tracks community growth with GitHub-native features. No personal data
beyond publicly available contribution information is collected.

## Signals tracked

- First-time contributors (GitHub marks these automatically on PRs).
- First merged PR.
- Total merged PRs per contributor.
- Issues completed (closed via merged PR or maintainer action).
- Review participation (reviews and comments on PRs).
- Repeat contributors (more than one merged PR).
- Active contributors over time (monthly).
- Contribution area: frontend, backend, tests, documentation, accessibility,
  security, performance.

## How to track

1. **GitHub Insights → Contributors** — built-in graphs of commits, additions,
   and deletions by contributor. Use this for the monthly summary.
2. **Issue/PR labels** — `good first issue`, `help wanted`, area labels, and
   `first-time contributor` (applied by GitHub) make filtering easy.
3. **GitHub Projects** — a "Contributor growth" project (if created) holds the
   curated issue shortlist and tracks status. Reuse an existing project rather
   than creating duplicates.
4. **First-time contributor recognition** — GitHub automatically labels PRs
   from new contributors. Maintainers should leave a welcoming comment and, on
   merge, add a thank-you in release notes.
5. **Monthly contributor summary** — once a month, post a short discussion or
   issue summarising new contributors, merged PRs by area, and repeat
   contributors. Keep it factual and respectful; no public leaderboard ranking
   individuals by "score".

## Contributor journey

1. Developer finds a suitable issue (README shortlist or `good first issue` label).
2. Developer comments that they want to work on it.
3. Maintainer confirms availability.
4. Developer submits a PR.
5. Maintainer reviews it.
6. Contributor receives constructive feedback.
7. Merged contributors receive genuine recognition (release notes, monthly summary).

## Recognition

- Acknowledgment in README (Contributors section) and release notes.
- Recognition of first merged contributions.
- Clear recognition of documentation, testing, code, and design work.
- No automated leaderboard; no invented names, avatars, jobs, or counts.

## Privacy

Only publicly available GitHub contribution information is used. Do not
collect email addresses, IP addresses, or other personal data. Never
automatically assign an issue to a developer without their agreement.
